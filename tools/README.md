# tools/

## `dump-sdk-offsets`

Emits `offsets/shared-memory.json` — the byte offsets into LMU's shared memory
block. It does not guess or scan: it asks the compiler for `offsetof` against
Studio 397's own header, so the numbers are correct by construction for
whichever SDK version you build against.

This is why `shared-memory.json` says *do not hand-edit* — regenerate it
instead.

### The headers are not in this repository

The dumper includes three Studio 397 Plugin SDK headers:

    SharedMemoryInterface.hpp   ->  includes InternalsPlugin.hpp
    InternalsPlugin.hpp         ->  includes PluginObjects.hpp

They are **not vendored here and must not be.** Their banner states:

> Copyright (c) 2025 Studio 397 BV and Motorsport Games Inc. All rights
> reserved. [...] Redistribution or modification of this header is not
> permitted.

That is a licence term, so this repository pins the SDK by *fingerprint*
instead of by content: `offsets/shared-memory.json` records
`sdkHeaderSha256`, and the build fails loudly if your copy differs from the one
the committed profile was generated against.

### Where to get them

They ship with the game. Every user already has them:

    <LMU install>\Support\SharedMemoryInterface\

On a default Steam install that is:

    C:\Program Files (x86)\Steam\steamapps\common\Le Mans Ultimate\Support\SharedMemoryInterface\

Copy all three `.hpp` files next to `dump-sdk-offsets.cpp`. They are covered by
`.gitignore`, so they cannot be committed by accident.

### Build and run

Needs the MSVC toolchain (`x64 Native Tools Command Prompt for VS`):

    cl /std:c++17 /EHsc /O2 dump-sdk-offsets.cpp
    dump-sdk-offsets.exe > ..\offsets\shared-memory.json

### When to re-run it

Only when the **SDK headers** change — that is, when a game update ships a
different `SharedMemoryInterface.hpp`. Compare against the recorded hash:

    (Get-FileHash "<LMU install>\Support\SharedMemoryInterface\SharedMemoryInterface.hpp" -Algorithm SHA256).Hash

If it matches `sdkHeaderSha256` in `offsets/shared-memory.json`, there is
nothing to do.

Note that this is a **different** trigger from the one that invalidates
`offsets/<build>.json`. Those are RVAs into the executable and move on *every*
patch; the shared-memory layout is a published interface and changes rarely.
Do not conflate them:

| File | Keyed by | Changes when | Regenerated by |
|---|---|---|---|
| `offsets/shared-memory.json` | SDK header SHA-256 | S397 revises the SDK (rare) | `dump-sdk-offsets` |
| `offsets/<build>.json` | executable SHA-256 | every game patch | `inactive-reset reanchor` |
